# buildq

**Одна Xcode-сборка за раз на весь Mac — для всех агентов и worktree.**

[English version](README.md)

Вы гоняете несколько AI-агентов параллельно (Claude Code, Codex, OpenCode…), каждого в своём
git worktree одного iOS-проекта, и каждый хочет собраться. Одна сборка большого приложения и так
занимает все ядра. Две параллельные почти не быстрее двух подряд, а параллельные `tuist generate`
ломают общие кэши. В итоге агенты падают по таймауту, сборки валятся без причины, и непонятно,
кто что собирает.

`buildq` — маленькая общая на машину FIFO-очередь для тяжёлых команд:

- **Строгий FIFO без гонок.** Номер тикета выдаётся под файловой блокировкой, а слот сборки — это
  `fcntl`-лок. Два агента, вставшие в очередь в одну и ту же миллисекунду, всё равно получат
  чёткий порядок и не пересекутся.
- **Устойчивость к падениям.** Если агент умер, ядро само освобождает слот. Если агента убили
  через SIGKILL посреди сборки, осиротевшая сборка держит слот, пока buildq её не остановит
  (SIGTERM, потом SIGKILL). Пересечений не бывает и в этом случае.
- **Удобно агентам.** `buildq run -- <cmd>` блокируется до конца сборки, в ожидании пишет позицию
  в очереди и возвращает код выхода команды. При ошибке выводит только строки `error:`.
- **Свой симулятор у каждого worktree.** `buildq sim` клонирует подготовленный базовый симулятор
  (залогинен, настройки выставлены). Слот занят только на время сборки, а установка и проверка
  идут вне очереди.
- **Хук для Claude Code.** Голые `xcodebuild` / `tuist generate` запрещаются, вместе с отказом
  агент получает инструкцию, как запустить их через очередь.
- **Приложение в строке меню.** Молоток-светофор, а в выпадающей панели — текущая сборка
  с прогрессом, очередь и последние результаты. Есть русский и английский.
- **Разбор полётов.** Полный лог каждого запуска и JSONL-журнал: кто кого ждал и почему.

CLI — один Python-файл без зависимостей, приложение — один SwiftUI-файл.

## Установка

Нужны macOS 13+ и `python3` 3.9+ (подойдёт тот, что из Xcode Command Line Tools). Для сборки
приложения в строке меню нужен Xcode 15+.

### Плагин Claude Code

```
/plugin marketplace add gruzd1sok/buildq
/plugin install buildq@buildq
```

Плагин добавляет скилл `buildq` и хук, а также кладёт `buildq` в PATH Bash-инструмента Claude.
Для приложения в строке меню, других агентов и своего терминала поставьте CLI и приложение
через Homebrew или из исходников.

### Homebrew

```bash
brew tap gruzd1sok/buildq https://github.com/gruzd1sok/buildq
brew install gruzd1sok/buildq/buildq
brew services start buildq      # приложение в строке меню при входе
```

### Из исходников

```bash
git clone https://github.com/gruzd1sok/buildq && cd buildq
make install                    # CLI -> ~/.local/bin, приложение -> ~/Applications + LaunchAgent
make install-cli                # только CLI
make uninstall
```

## Использование

```bash
buildq run --label "фикс логина" --log /tmp/build.log -- \
  xcodebuild -workspace App.xcworkspace -scheme App -destination "id=$(buildq sim --no-boot)" build

buildq status                   # кто собирается, кто ждёт, последние сборки
buildq cancel <pid|тикет>       # снять сборку из очереди или остановить
buildq events --kind finished,timeout
```

| Код выхода | Значение |
|---|---|
| код команды | команда отработала |
| 75 | не дождался слота за `--max-wait` минут (по умолчанию 120, `0` — ждать вечно) |
| 128+N | buildq остановлен сигналом N (например, 143 после `buildq cancel`) |

### Симуляторы

```bash
buildq sim --refresh-base --source "iPhone 16 Pro"   # один раз: снимок вашего подготовленного симулятора
UDID=$(buildq sim)                                   # клон этого worktree "wt-<папка>", загружен
xcrun simctl install "$UDID" path/to/App.app
buildq sim --rm                                      # когда worktree удалён
```

`--refresh-base` на несколько секунд выключает исходный симулятор: запущенный симулятор
клонировать нельзя.

## Приложение в строке меню

| Молоток | Значение |
|---|---|
| серый контур | очередь пуста |
| зелёный, закрашен | идёт сборка, ошибок нет, никто не ждёт |
| зелёный контур | последняя сборка успешна (5 минут) |
| жёлтый, закрашен | идёт сборка и кто-то ждёт, или сборка в 1,5 раза дольше обычного, или её агент умер |
| красный, закрашен | в текущей сборке уже есть ошибки компиляции |
| красный контур | последняя сборка упала (15 минут) |

Причину текущего цвета показывают подсказка и шапка панели.

## Настройка

Свои тяжёлые команды проекта можно добавить в хук через `~/.buildq/config.json`. Пример —
в [`examples/config.json`](examples/config.json), подробности — в [README](README.md#configuration).

## Разработка

```bash
make test       # юнит- и конкурентные тесты, покрытие локализации
make app        # build/BuildQBar.app
```

Строки интерфейса хранятся в `app/Localizable.xcstrings`. `make test` падает, если строки нет
в каталоге или у неё нет перевода.
